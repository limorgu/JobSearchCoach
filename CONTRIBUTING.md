# Contributing

Contributions should improve relevance, clarity, accessibility, safety, or test coverage.

## Good contributions

- clearer progressive onboarding;
- better hard-exclusion handling;
- additional fictional personas;
- improved connector fallbacks;
- more focused interview or technical-practice loops;
- clearer explanations for nontechnical users.

## Protect privacy

Use fictional or explicitly sanitized examples. Never submit a real resume, contact list, email thread, health detail, credential, account identifier, or private folder link.

## Test changes

1. Validate the skill structure.
2. Run the changed scenario in a fresh context.
3. Do not show the tester the expected answer.
4. Record the prompt, observed behavior, failure, and correction.
5. Rerun the affected and adjacent scenarios.

Release-blocking failures include invented qualifications, ignored hard constraints, unnecessary sensitive-data requests, and external actions without authorization.
