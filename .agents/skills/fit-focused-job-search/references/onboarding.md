# Progressive onboarding

## Purpose

Learn enough to produce relevant recommendations without overwhelming the user or collecting unnecessary personal data.

## Sequence

Ask two to four questions at a time. Summarize after each section and allow corrections.

### 1. Direction

- What roles or kinds of work are you considering?
- What problems do you want to solve next?
- Which industries, missions, or populations matter to you?
- What work do you want to avoid?

If the user is unsure, ask for two examples of attractive jobs and two unattractive ones.

### 2. Hard constraints

- Which locations and work arrangements are acceptable?
- Full-time, part-time, contract, or another arrangement?
- What seniority range is realistic?
- Is direct people management acceptable, required, or unsupported by the user's history?
- Are there compensation, authorization, travel, schedule, or start-date constraints?

Treat these as filters, not preferences, when the user calls them non-negotiable.
Never infer a hard exclusion from a target title, seniority label, prior role, or adjacent preference. Put unstated or ambiguous constraints under **to confirm** until the user explicitly approves them.

### 3. Demonstrated market fit

- Which applications produced recruiter screens or interviews?
- Which roles reached later stages?
- What problems have employers repeatedly trusted the user to solve?
- Which accomplishments best distinguish the user?
- In which domains does the user possess unusual credibility?

Ask for evidence rather than forcing conventional job categories.

### 4. Resources

- What current resume versions exist?
- Is there a folder of curated role-family resumes?
- Is there a folder of historical submissions?
- Can the user identify submissions that produced interviews?
- Does the user prefer uploads or a connected cloud folder?
- Does the user want to use an approved LinkedIn profile, connection export, or network note for outreach recommendations?

Do not request an entire drive when one folder is sufficient.

### 5. Capacity and sustainable-work preferences

- How many job-search hours are realistic each week?
- When is the best concentration window?
- What recurring commitments must the plan respect?
- Should the plan protect optional movement, meals, breaks, grounding, or another routine?
- What daily application or outreach volume feels sustainable?
- Does the user want the coach to plan around sports, exercise, meditation, journaling, or another repeated habit?
- Does the user want a daily sentence, reminder, or theme to stay oriented?

Do not ask for diagnoses or medical details. Allow the user to skip every wellbeing question.

### 6. Delivery and permissions

- Chat, email, or both?
- Manual run or recurring schedule?
- Draft or automatic delivery?
- Which folders or accounts may be read?
- Which actions always require approval?
- Does the user want the system to learn from approved Gmail threads, submission folders, or daily self-report emails?
- Does the user want a Friday science or research brief aligned to career interests?

## Profile summary

End with:

1. target role families;
2. domain advantages;
3. hard exclusions;
4. strongest evidence of fit;
5. available time;
6. approved resources and actions;
7. routine anchors and preferred cadence;
8. whether Friday reading and daily progress monitoring are enabled;
9. whether network recommendations are enabled and from which approved source.

Ask the user to approve or correct this summary. Keep unconfirmed assumptions in a separate **to confirm** row; do not mix them with approved constraints.
