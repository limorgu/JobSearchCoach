# Evidence and fit evaluation

## Evidence hierarchy

Use signals in this order while preserving uncertainty:

1. Prior applications that produced interviews or recruiter interest
2. Work the user performed successfully with measurable outcomes
3. Repeated responsibilities across roles or projects
4. Domain expertise supported by education, research, clinical, community, or lived professional practice
5. Transferable capabilities inferred cautiously from adjacent work
6. Aspirational interests without evidence

An interview is evidence that the profile can be competitive for analogous work. It is not proof that every job with the same title fits.

## Role-family map

Group opportunities by the problems and capabilities they require, for example:

- product or program leadership;
- research, behavioral science, or measurement;
- applied data science or analytics;
- human data, evaluation, safety, or quality;
- education, therapy, health, support, content, media, HR/People, or knowledge systems.

Allow a user to belong to several families. Avoid collapsing an interdisciplinary profile into one conventional title.

## Hard exclusion sequence

Before scoring, verify:

1. role is open and direct application source is credible;
2. location and work arrangement meet constraints;
3. employment type is acceptable;
4. required people-management experience is supported;
5. central technical requirements are supported;
6. credentials, licensing, authorization, and travel requirements are supported;
7. work is not primarily something the user excluded.

If a hard requirement is unclear, mark it for verification or exclude it from a short final list.
Apply user constraints as hard exclusions only when the user stated or approved them. Label reasonable but unconfirmed inferences explicitly and ask before filtering on them.

## Fit dimensions

Score with explicit evidence:

- problem and domain alignment: 0-3;
- demonstrated responsibilities: 0-3;
- methods and tools: 0-2;
- seniority and scope: 0-1;
- motivation and constraints: 0-1.

Do not let preferred qualifications erase strong evidence in required dimensions. Do not let enthusiasm compensate for a missing central requirement.

## Recommendation labels

- **Apply:** strong required-qualification fit, acceptable constraints, and credible evidence.
- **Consider:** meaningful alignment but one uncertainty or non-central gap needs a conscious decision.
- **Skip:** hard exclusion, central unsupported requirement, weak problem alignment, or poor tradeoff.

## Report quality

Return only strong matches. A useful no-match report is better than padded results. Explain why the user's interdisciplinary or domain background is an advantage when the job supports that inference.
